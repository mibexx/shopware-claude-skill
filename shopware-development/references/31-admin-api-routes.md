# Admin API routes, integrations and Sync API (reference, Shopware 6.7.15.1)

## 1. Purpose

This reference applies when a plugin provides its own endpoints under `/api/...`, when external systems access the Admin API via an integration (OAuth `client_credentials`), or when bulk data is written via the Sync API (`/api/_action/sync`).

Scope: Store API routes (`/store-api/...`) in [T-30 Store API routes](./30-store-api-routes.md); ACL roles and privileges UI in [T-23 ACL](./23-acl-permissions-roles.md); calls from the Administration (`ApiService`) in [T-26 Admin data handling](./26-admin-data-handling.md); Storefront controller basics in [T-16 Controller/Pages](./16-storefront-controller-pages.md); DAL in [T-27](./27-dal-entities.md) and [T-28](./28-dal-reading-writing.md).

## 2. Concepts

- **Admin API route**: Symfony controller (extends `AbstractController`) with class default `_routeScope = ['api']`. The path must start with `/api/` (`ApiRouteScope::ALLOWED_PATH = 'api'`). Convention for actions: `/api/_action/<plugin>/<action>`.
- **Auth**: Default `auth_required = true`. `ApiRouteScope::isAllowed()` then requires an `AdminApiSource` (user or integration). The bearer token is checked by `ApiAuthenticationListener::validateRequest` (`KernelEvents::CONTROLLER`). Only `defaults: ['auth_required' => false]` (e.g. `/api/oauth/token`) also allows `SystemSource` and skips the token check.
- **Privileges**: Route default `PlatformRequest::ATTRIBUTE_ACL` (`_acl`) = list of privilege strings. `AclAnnotationValidator` checks each string with `Context::isAllowed()`. An `AdminApiSource` with `admin = true` may do everything, otherwise only strings from its roles.
- **OAuth** (`POST /api/oauth/token`, `AuthController::token`): grants `password`, `refresh_token`, `client_credentials`, SSO grant (`ShopwareGrantType`), `authorization_code` (`ShopwareAuthCodeGrantType`). Integrations: `client_credentials` with `client_id` = access key ID (`SWIA...`), `client_secret` = secret access key. TTL: access token `PT10M`, refresh token `P1W`, auth code `PT5M`.
- **Generic endpoints** are generated by `ApiRouteLoader` per entity definition: `GET/POST /api/<entity>`, `GET/PATCH/DELETE /api/<entity>/{id}`, `POST /api/search/<entity>`, `/api/search-ids/<entity>`, `/api/aggregate/<entity>`. Entity name `snake_case` becomes path `kebab-case` (`product_manufacturer` -> `/api/product-manufacturer`).
- **Sync API**: `POST /api/_action/sync` (`SyncController::sync`), payload = object of operations `{entity, action: upsert|delete, payload|criteria}`.

Directory tree (plugin-relative):

```
SwagExample/
├── composer.json
└── src/

    ├── Api/DemoController.php
    └── Resources/
```

Decision guide: Custom logic = own controller under `/api/_action/<plugin>/...`. Pure data maintenance of an entity = generic endpoints or Sync API, no controller needed. Consumers are customers/Storefront = Store API ([T-30](./30-store-api-routes.md)).

## 3. Instructions

1. Create the **controller**: class route with `_routeScope = ['api']`, method routes with path `/api/_action/<plugin>/...`, a unique `name` (`api.action.<plugin>.<x>`) and `methods`.
2. Set the **permission** via `_acl`: entity privileges (`product:read`, `product:update`) or a custom string (core examples: `api_send_email` in `MailActionController`, `integration:create` in `IntegrationController`). Custom strings must be offered in role management via `sw-privileges` ([T-23](./23-acl-permissions-roles.md)). Admin users (`admin=true`) bypass everything.
3. Create **`routes.php`** and **`services.php`** (controller `public`, `setContainer`). The PHP format is confirmed: `Bundle::configureRoutes` loads `Resources/config/routes.php` or `routes/*.php`.
4. Install and check:
   ```bash
   bin/console plugin:refresh && bin/console plugin:install --activate SwagExample && bin/console cache:clear
   bin/console debug:router | grep swag_example
   ```
5. **Create an integration**: Administration -> Settings -> System -> Integrations (provides access key ID and secret). Backend: `IntegrationController` (`POST /api/integration`, `PATCH /api/integration/{id}`); keys via `GET /api/_action/access-key/intergration` (the typo in the path is like that in the code, `AccessKeyController`). Roles via `aclRoles` or `admin=true` (can only be set by an admin, otherwise `PermissionDeniedException`).
6. **Get a token**: `POST /api/oauth/token` with JSON `grant_type=client_credentials`, `client_id`, `client_secret`. Rate limit `RateLimiter::OAUTH` (config `shopware.api.rate_limiter`).
7. **Call** with `Authorization: Bearer <token>`. Useful headers (`PlatformRequest`): `sw-language-id`, `sw-version-id`, `sw-include-seo-urls`, `sw-expect-packages`, `indexing-behavior`, `indexing-skip`, `indexing-only` (Sync).
8. **From the Administration**: `ApiService` with `apiEndpoint = '_action/swag-example'` (without `/api`, since `httpClient.baseURL` = `/api`), see [T-26](./26-admin-data-handling.md).
9. **API docs locally**: `/api/_info/stoplightio.html`, OpenAPI via `api.info.openapi3` (`InfoController`), entity schema `/api/_info/entity-schema.json`.

## 4. Examples

`src/Api/DemoController.php`

```php
<?php declare(strict_types=1);

namespace SwagExample\Api;

use Shopware\Core\Framework\Context;
use Shopware\Core\Framework\DataAbstractionLayer\EntityRepository;
use Shopware\Core\Framework\DataAbstractionLayer\Search\Criteria;
use Shopware\Core\Framework\Routing\ApiRouteScope;
use Shopware\Core\PlatformRequest;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\JsonResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\Routing\Attribute\Route;

#[Route(defaults: [PlatformRequest::ATTRIBUTE_ROUTE_SCOPE => [ApiRouteScope::ID]])]
class DemoController extends AbstractController
{
    /**
     * @param EntityRepository<\Shopware\Core\Content\Product\ProductCollection> $productRepository
     */
    public function __construct(private readonly EntityRepository $productRepository)
    {
    }

    #[Route(
        path: '/api/_action/swag-example/greet',
        name: 'api.action.swag_example.greet',
        defaults: [PlatformRequest::ATTRIBUTE_ACL => ['product:read']],
        methods: [Request::METHOD_POST]
    )]
    public function greet(Request $request, Context $context): JsonResponse
    {
        $name = $request->request->getString('name', 'World');
        $count = $this->productRepository->searchIds(new Criteria(), $context)->getTotal();

        return new JsonResponse(['message' => \sprintf('Hello %s', $name), 'products' => $count]);
    }
}
```

`Context` is injected via an argument resolver (as in `SyncController::sync(Request, Context)`). JSON bodies end up in `$request->request` via `JsonRequestTransformerListener`.

`src/Resources/config/routes.php`

```php
<?php declare(strict_types=1);

use Symfony\Component\Routing\Loader\Configurator\RoutingConfigurator;

return static function (RoutingConfigurator $routes): void {
    $routes->import('../../Api/**/*Controller.php', 'attribute');
};
```

`src/Resources/config/services.php`

```php
<?php declare(strict_types=1);

use SwagExample\Api\DemoController;
use Symfony\Component\DependencyInjection\Loader\Configurator\ContainerConfigurator;

use function Symfony\Component\DependencyInjection\Loader\Configurator\service;

return static function (ContainerConfigurator $container): void {
    $container->services()->set(DemoController::class)
        ->public()
        ->args([service('product.repository')])
        ->call('setContainer', [service('service_container')]);
};
```

The plugin base class loads `Resources/config/services.*` via `Bundle::registerContainerFile` (PHP/YAML/XML loader; XML deprecated; called in `build()`). The `public()` + `setContainer` pattern matches the core controllers.

Call with an integration:

```bash
BASE=http://localhost:8000
TOKEN=$(curl -s $BASE/api/oauth/token -H 'Content-Type: application/json' \
  -d '{"grant_type":"client_credentials","client_id":"SWIA...","client_secret":"..."}' | jq -r .access_token)

curl -s -X POST $BASE/api/_action/swag-example/greet \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"name":"Mike"}'
```

Generic endpoints:

```bash
curl -H "Authorization: Bearer $TOKEN" "$BASE/api/product?limit=10&total-count-mode=1"
curl -X POST $BASE/api/search/product -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"limit":5,"filter":[{"type":"equals","field":"active","value":true}],"associations":{"manufacturer":{}},"total-count-mode":1}'
# more: POST /api/search-ids/product, POST /api/aggregate/product,
# GET /api/product/{id}/manufacturer, POST /api/_action/clone/product/{id}, POST /api/_action/version/product/{id}
```

Sync API:

```bash
curl -X POST $BASE/api/_action/sync -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' -H 'indexing-behavior: use-queue-indexing' \
  -d '{
    "write-manufacturers": {"entity":"product_manufacturer","action":"upsert",
      "payload":[{"id":"0189...32hex","name":"ACME"}]},
    "del-old": {"entity":"product","action":"delete",
      "criteria":[{"type":"equals","field":"productNumber","value":"OLD-1"}]}
  }'
```

Structure (`SyncOperation::createFromArray`): `entity` (required), `action` in {`upsert`,`delete`} (required), `payload` OR `criteria` (at least one not empty), optional `key` (otherwise the JSON key). Response `SyncResult`: `data` (written IDs per entity), `notFound`, `deleted`. `criteria` acts as a filter list, ACL check via `AclCriteriaValidator`.

More examples: templates for the plugin scaffold under [../templates/plugin/README.md](../templates/plugin/README.md); for Admin-side calls see [T-24 Admin modules](./24-admin-modules.md) and [T-26](./26-admin-data-handling.md).

## 5. Pitfalls

- **`_routeScope` missing**: the request is rejected (`RoutingException::invalidRouteScope`). `AbstractRouteScope::$allowedPaths` restricts the `api` scope to paths `/api/...`.
- **`_acl` forgotten**: every authenticated Admin API client (including an integration with any role) may call the route. UI privileges (`meta.privilege`) secure nothing.
- **`auth_required => false` on Admin routes**: the route is reachable without a token. Only intended for the token endpoint.
- **Controller not public / without `setContainer`**: `AbstractController` helpers fail or the route cannot be resolved.
- **Generic paths**: `POST /api/product` with an existing ID fails; upsert/idempotency only via Sync API or PATCH.
- **Sync without `payload`/`criteria`** or invalid `action`: `ApiException::invalidSyncOperationException`. `payload` must be a list of assoc arrays (otherwise 400 "Invalid payload").
- **Large Sync imports**: indexing takes time. `indexing-behavior: use-queue-indexing` or `disable-indexing` (`EntityIndexerRegistry::USE_INDEXING_QUEUE/DISABLE_INDEXING`), `indexing-skip: product.indexer,...`.
- **`limit` > `shopware.api.max_limit`** (default 500) is capped.
- **Token valid for 10 min**: integrations must request a new one via client credentials on 401.
- **Write protection**: `integration.admin` is `WriteProtected(SYSTEM_SCOPE)->allowWriteThroughAdminApi()`; direct DAL writes fail, only via the controller.
- **Path typo**: `/api/_action/access-key/intergration` really is spelled like that.

### Deprecations and version notes (6.5/6.6 -> 6.7)

- Attributes `#[Route]` (`Symfony\Component\Routing\Attribute\Route`); `@Route`/`@Acl` annotations no longer exist (the 6.5 docs partly still show them). `_acl` is a route default.
- **XML routes/services/packages are deprecated** (`@deprecated tag:v6.8.0`, `Bundle::triggerXmlConfigDeprecation`, no longer loaded in 6.8). Use the PHP format.
- The `/api/v1/...` prefix is no longer common; only `/api/v1/_info/version` remains as a legacy route (`InfoController`).
- `GET /api/_info/queue.json` is `@deprecated tag:v6.8.0` (-> `message-stats.json`).
- New in the 6.7 code: SSO grants (`Shopware\Core\Framework\Sso`), `authorization_code` with PKCE for public clients (`shopware.api.oauth_clients`), scope `user-verified`, `integration.mcp_allowlist` (JSON, see [T-44 MCP server](./44-mcp-server.md)). From which minor version exactly: not confirmed.

## 6. Checklist

- [ ] Class route with `_routeScope = ['api']`, path starts with `/api/`
- [ ] Route name unique (`api.action.<plugin>.<x>`), `methods` set
- [ ] `_acl` set with appropriate privileges
- [ ] Controller `public` + `setContainer` in `services.php`
- [ ] `routes.php` (PHP, not XML) imports the controller
- [ ] `debug:router` shows the route after install and `cache:clear`
- [ ] Integration created with the minimal necessary role (not `admin=true`)
- [ ] For Sync imports, indexing headers chosen deliberately
- [ ] Calls from the Administration without `/api` prefix in `apiEndpoint`
