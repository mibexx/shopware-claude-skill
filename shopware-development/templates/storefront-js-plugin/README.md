# Template: Storefront JS plugin (SwagExample)

Purpose: Plugin with a custom storefront JS plugin (ES class extending `PluginBaseClass`), registration in `main.js`, integration via a `data` attribute in Twig and a commented-out example of overriding a core plugin. Shopware 6.7.15.1.

## File tree

```
SwagExample/
├── composer.json
└── src/
    ├── SwagExample.php
    └── Resources/
        ├── snippet/storefront.{de,en}.json
        ├── views/storefront/base.html.twig                       # data attribute on the button
        └── app/storefront/src/
            ├── main.js                                           # MANDATORY entry point, registration
            ├── swag-example/swag-example.plugin.js               # plugin class
            └── override/swag-example-scroll-up.plugin.js         # example: extending a core plugin
```

Build output (not in the scaffold, generated by the build): `src/Resources/app/storefront/dist/storefront/js/swag-example/swag-example.js`. Check it in when shipping via Composer/store.

## Integration / CLI

```bash
bin/console plugin:refresh
bin/console plugin:install --activate SwagExample
bin/build-storefront.sh          # build JS (the storefront loads dist/, not src/)
bin/console theme:compile --sync # if old files are being served
bin/console cache:clear
# Development with hot reload:
bin/watch-storefront.sh
```

Check in the browser: `window.PluginManager.getPluginList()` and `window.PluginManager.getPluginInstances('SwagExample')`.

## Rules (verified against the source code)

- `src/Resources/app/storefront/src/main.js` (or `main.ts`, takes precedence) is mandatory. Without the file the bundle is silently ignored.
- Plugin class: `init()` is mandatory (otherwise console warning), `static options` for defaults, `this.$emitter.publish/subscribe` for events, implement `destroy()` and remove all listeners outside `this.el` there.
- Options merge: `static options`, constructor options, `data-<name>-config`, `data-<name>-options` (JSON).
- Async registration `() => import(...)` is the core standard. Without a prototype the manager recognizes it as async.
- `PluginManager.override(name, Class, selector)` replaces the complete registration. The new class must extend the core plugin (`extends`), otherwise its functionality is missing. In practice only one override per plugin is possible; events (`$emitter.subscribe('event.Namespace', ...)`) are conflict-free.
- After AJAX reloading: `window.PluginManager.initializePluginsInParentElement(el)`.
- Twig: `{% sw_extends %}`, block `base_main_inner` (inside `<main>`) comes from `storefront/base.html.twig`; it is also overridden by `page/content/index` and `page/content/product-detail` (⚠ there only effective with `parent()`). The toggle button sets `aria-controls`/`aria-expanded`, the JS toggles `aria-expanded`.
- External scripts as a `<script>` tag: in the block `base_body_script` (`base.html.twig`, always call `{{ parent() }}`).

## Avoiding deprecations

- `HttpClient` (`src/service/http-client.service`): `@deprecated tag:v6.8.0`, use `fetch()` instead.
- `DomAccess` (`src/helper/dom-access.helper`): entirely `@deprecated tag:v6.8.0`, use the native DOM API instead.
- Core plugins `FormValidation`, `FormSubmitLoader`: deprecated, replacement `FormHandler`.
- Block `layout_head_javascript_hmr_mode` (docs recommendation for script tags) is `@deprecated tag:v6.8.0` in 6.7.15.1, hence `base_body_script`.

## Gaps and notes

- ⚠ UNVERIFIED: The scaffold was not built and not tested in the browser (JS syntax via `node --check`, JSON via `JSON.parse`, signatures and block name checked against the source code).
- ⚠ UNVERIFIED: `import ... from 'src/plugin/scroll-up/scroll-up.plugin'` in the override example assumes the webpack alias `src` pointing to the core storefront (core code uses the same import style). The example is commented out in `main.js`.
- ⚠ UNVERIFIED: Behavior of `PluginManager.override()` with core plugins using async registration (derived from `plugin.manager.js`, not verified in the browser). The docs variant `getPlugin('X').get('class')` only returns the loader function for async plugins, so the class is imported directly here.
- ⚠ UNVERIFIED: Behavior of `bin/watch-storefront.sh` in Vite/importmap mode (feature flag `v6.8.0.0`).
- ⚠ GAP: Visible styling of the button/target (`.is-open`) is not included. The SCSS entry point of a plugin would be `src/Resources/app/storefront/src/scss/base.scss` (see [theme](../theme/README.md)).
